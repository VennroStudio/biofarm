# Партнёрская программа: утверждённый объём

Пользователь разрешил полную реализацию 17.09.2026. Работа в main, без новой ветки. Проверки на локальных тестовых пользователях; никаких реальных переводов, писем или CRM-запросов при тестировании.

## Правила

- Обычный пользователь получает реферальную ссылку. Администратор назначает партнёра.
- При назначении партнёром обнуляется его текущий пригласивший; все потомки остаются под ним. Будущие покупки этой ветки больше не оплачивают прежнюю команду. Снимки старых заказов сохраняются.
- Признак isReferral вычисляется из referredByUserId, в админке показываются оба; отдельный противоречивый boolean не хранится.
- Реферальные начисления четырём предкам: 1%, 0.5%, 0.25%, 0.25%; ближайшему партнёру независимо от глубины ещё 1%; покупателю 1% покупательскими бонусами. Это настраиваемые стартовые значения, не гарантия прибыльности; потолок 4%. Статусов/квалификаций/обязательных покупок нет.
- Привязка зарегистрированного покупателя имеет приоритет над ссылкой. Для гостя используется проверенный код. Первое приглашение хранится до 30 дней. Самопривязки и циклы запрещены.
- База вознаграждения: оплаченная часть товаров после скидки и списания бонусов, доставка исключена. Денежные комиссии хранятся в копейках; округление вниз, без float-денег. Снимок ставок/получателей/позиций при создании заказа.
- Участие не платное; никаких приветственных начислений. Исторический журнал не удаляется.
- Покупательские бонусы отдельно от денежных комиссий. Старый неподтверждённый остаток не превращается автоматически в деньги на вывод.
- Начисление только после подтверждённой оплаты. Доступность после доставки и настраиваемого удержания (начальный пример 14 дней, это бизнес-удержание, не заявление о сроке законного возврата).
- Бонусы при оформлении резервируются, списываются после оплаты, освобождаются при отмене. Нет двойного расхода одновременно в заказах/выплатах.
- Возвраты по позициям, с исходными скидками/бонусами/ставками. Подтверждённый возврат отменяет соответствующие начисления и восстанавливает использованные бонусы. Уже выплаченное учитывается как долг будущих начислений. Сам возврат покупателю от этого не зависит.
- Выплаты только вручную: pending -> approved -> paid; rejected освобождает резерв; paid требует платёжного подтверждения. Кнопка approve не означает перевод.
- Партнёр создаёт многократно используемую корзину (не заказ) с непрогнозируемым токеном, сроком, товарами, количеством, промокодом. Цены/наличие проверяются вновь. QR содержит только URL. Старую корзину не стирать без явного выбора.
- Партнёр запрашивает промокод; администратор утверждает ограничения/срок/скидку. Промокод не меняет команду.
- Кабинеты являются вкладкой существующего личного кабинета. Отдельная админская страница управления программой. Настройки ставок, бюджета, удержания, выплат, исключений; симулятор, журнал, дерево, исправления привязок с причиной.
- ЮKassa: создание платежа, return URL не считается оплатой, webhook проверяется GET у провайдера, идемпотентность в БД, сверка зависших платежей, полные/частичные возвраты, данные чеков. Ключи только из окружения, не выдаются frontend. Без ключей честное состояние «не настроено», без фиктивной оплаты.

## Ограничения проекта

PHP 8.4+, Slim, Doctrine, Twig, React islands. Существующие API и формы сохранять совместимыми. Миграции вручную не писать (docs/agent-rules.md); новые таблицы описывать ORM metadata. Локальную добавочную схему применять только после просмотра сгенерированного Doctrine SQL. Production не изменять.

## Приёмка

Тестовая цепочка партнёр + 5 пользователей, создание/оплата нескольких заказов, отсутствие начисления до оплаты, все 4 уровня и глубокий партнёр, повышение с отделением ветки, полные/частичные возвраты, повторные события, резерв/отклонение/ручная выплата, ограничения доступа, ставки/потолок, корзины и промокоды. Реальный провайдер требует тестовых ключей; без них проверять контракт через mock transport и явно обозначить ограничение.
