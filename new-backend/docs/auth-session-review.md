# Продление входа в личный кабинет — 2026-09-16

## Причина

- `JwtTokenService` выдаёт access token на 900 секунд и refresh token на 2592000 секунд.
- `assets/react/site/api.ts` раньше удалял access token и пользователя после любого HTTP 401, не вызывая существующий `POST /v1/auth/refresh`.
- `CheckoutPage.tsx` также удалял авторизацию при любой ошибке загрузки профиля или адресов, включая сетевые ошибки.

## Исправление

- После 401 авторизованного запроса клиент обновляет access token через HTTP-only refresh cookie и повторяет исходный запрос один раз, сохраняя метод и тело.
- Одновременные запросы используют один Promise; вкладки координируются через Web Locks, если API доступен. Поздний 401 использует уже обновлённый токен.
- Отсутствующая cookie (422), отозванный refresh token (401) или повторный 401 завершают вход. Сетевые ошибки и 5xx сохраняют авторизацию для повторной попытки.
- Ответ обновления не восстанавливает вход после локального выхода. Гостевые запросы не запускают обновление. Ошибки входа не обновляют токены.
- Кабинет перенаправляет на вход только при потере авторизации; checkout больше не удаляет её при временной ошибке.

## Проверка

- Первоначальный набор: 9 из 10 тестов воспроизвели отсутствие продления входа; после исправления и расширения набора проходят 12 тестов. Запуск: `npm test` (Node 22).
- `npm run check`: TypeScript, ESLint, Vite проходят. Существующее предупреждение сборки о production.webp не связано с авторизацией.
- Реальный локальный HTTP: вход тестового пользователя → подписанный просроченный access token → 401 → refresh → 200 → профиль того же пользователя. Refresh cookie ротируется; старая отклоняется с 401; отсутствие cookie даёт 422. Отдельная тестовая HTTP-сессия завершена через logout.
- Браузер: вход и перезагрузка страницы профиля; кабинет загружает данные. Истечение срока проверено через API и автотесты, без ожидания 15 минут в браузере.
- Работа выполнена в `main`; серверные сроки токенов и проверки авторизации не изменены.

## Справочные материалы

- [MDN: Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) — координация вкладок одного origin; API доступен в защищённом контексте.
- [MDN: Request.credentials](https://developer.mozilla.org/en-US/docs/Web/API/Request/credentials) — отправка и сохранение cookie при `same-origin`.
